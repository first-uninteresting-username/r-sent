# r-sent

A simple plaintext presentation tool for Wayland, written in Rust and inspired by
suckless `sent`. Every paragraph of a text file is one slide; text is scaled to the
largest size that fits, images are scaled to fit. See [SPEC.md](SPEC.md) for the full
behaviour and `man ./r-sent.1` for the manual.

```
r-sent [-v] [file] [config]
```

```
r-sent

@diagram.png

why plain text
- diffable
- no tooling
# comment, not shown
\# shown, starts with a hash
```

Try the demo: `r-sent example/presentation.txt` (the images are generated by
`example/make-images.py`).

Default keys: `→ Return space l j ↓ PgDn n` next, `← BackSpace h k ↑ PgUp p` previous,
`r` reload, `f` toggle fullscreen, `q`/`Escape` quit. Left click/scroll down next,
right click/scroll up previous.

## Configuration

Defaults live in `config.def.toml`. At build time it is copied to `config.toml`
(git-ignored), validated and embedded; edit `config.toml` and rebuild to change the
defaults. At run time, `~/.config/r-sent/config.toml` and then the `config` argument
override individual keys (arrays such as `keys` are replaced as a whole).

## Building

```sh
nix build            # flake package for x86_64-linux and aarch64-linux
devenv shell         # development shell (Rust, libxkbcommon, clippy/rustfmt hooks)
cargo build --release
cargo test
```

Runtime dependencies: `libwayland`-speaking compositor, `libxkbcommon`, system fonts
(DejaVu Sans by default), and `bunzip2` for the default `.ff.bz2` filter.

## Notes on the specification

- In the spec's `config.def.toml`, `mouse`, `keys` and `filters` follow the `[layout]`
  header, which in TOML would make them `layout.*` keys. They are top-level arrays per
  §4.3, so they are placed before the first table header.
- Runtime override order: embedded config, then the XDG user file, then the `config`
  argument (the most explicit source wins).
- The text block width is capped at the usable width, so a line that does not fit even
  at scale 0 is truncated with `...` (§7.3).
- After a `configure` that changes the size, the new frame is drawn right away so the
  next commit matches the acknowledged size; other redraws wait for a frame callback.
